# 记录模型

## 目录结构

```text
<健康档案根目录>/
├── 成员索引.md
├── <成员称呼>/
│   ├── 成员资料.md
│   ├── 01-健康档案/
│   │   ├── 健康概况.md
│   │   ├── 健康事件.md
│   │   ├── 健康摘要.md
│   │   ├── 待关注事项.md
│   │   ├── 健康事件附件/
│   │   └── 健康指标/
│   ├── 02-就医记录/
│   │   └── <年份>/<日期>-<主题>-<机构>/
│   │       ├── 就诊记录.md
│   │       └── <原始医疗文件>
│   └── 03-分类追踪/
│       └── <主题>/追踪概览.md
└── <另一成员称呼>/...
```

成员目录直接位于根目录。只有实际需要时才创建 `健康事件附件`、具体指标文件或分类主题；不要预建空层级。

## 稳定标识

目录名用于人类浏览，稳定 ID 用于关联：

| 对象 | 格式示例 |
|-|-|
| 成员 | `CY-P001` |
| 健康事件 | `SJ-20260930-001` |
| 健康指标记录 | `ZB-20261002-001` |
| 就诊 | `JZ-20261002-001` |
| 医疗文档 | `WD-20261002-001` |

同一成员内 ID 必须唯一。事件 ID 中的日期是记录创建日期，不代表症状开始日期。不要仅靠文件名或姓名关联记录。

## 三个目录的职责

### 01-健康档案

表示成员当前健康状态和结构化纵向数据：

- `健康概况.md`：既往史、手术史、当前用药、过敏、家族史、疫苗概况。
- `健康事件.md`：少量简单事件使用表格；反复发作、待确认字段较多或需要就诊前摘要的事件链接到 `健康事件附件/`。
- `健康指标/`：每种字段结构明显不同的指标使用独立 CSV。
- `健康摘要.md`：使用 `assets/health-summary-template.md` 生成的当前摘要。
- `待关注事项.md`：经用户确认的待问医生问题和待补资料。

### 02-就医记录

一次就医是原始医疗材料的主要归档单元。`就诊记录.md` 至少包含：

```yaml
---
记录ID: JZ-20261002-001
成员ID: CY-P001
日期: 2026-10-02
状态: 已完成
机构: 某医院
科室: 神经内科
相关健康事件:
  - SJ-20260928-001
相关健康指标: []
相关医疗文档: []
分类主题: []
---
```

原始报告和影像保留原文件名；必要时用同名 `.md` 伴随文件记录文档 ID、来源、报告日期、相关就诊和提取状态。

### 03-分类追踪

提供跨年份、跨就诊的主题视图，例如心脏、牙齿、眼睛、体检或疫苗接种。这里只保留索引、趋势和来源明确的结论，通过相对链接引用 `01` 和 `02`，不复制原始 PDF、图片或 CSV。

## 关联规则

- 症状可以先于就诊存在，后续再补 `相关就诊`。
- 医院测得的指标同时记录 `就诊ID` 和 `来源文件`；居家或设备数据可以没有就诊 ID。
- 就诊记录列出其相关事件、指标、文档和分类主题。
- 分类追踪引用事实记录，不成为事实的唯一来源。
- 同一原始文件只保存一次。需要多视角访问时使用相对链接，不复制文件。

## 时间精度

- `记录日期` 表示写入档案的日期，可以精确到日。
- `发生时间` 或 `开始时间` 必须忠实于用户或来源提供的精度，例如 `约 2026-09` 或 `最近几周（截至 2026-09-30）`。
- 不得用记录日期代替未知的症状开始日期。
- 未确认的事件状态写 `待确认`，不默认“观察中”“已缓解”或“已完成”。

## 来源状态

对关键内容使用以下状态之一：

- `用户自述`
- `设备测量`
- `报告原文`
- `医生诊断`
- `整理推断`
- `待确认`

只有前四项可直接进入事实摘要。`整理推断` 只能进入单独的“整理说明或待医生判断”部分并保留限定语；`待确认` 不能补全。

事件表只保存纯用户自述的简要索引。设备数据、报告值和医生意见使用独立记录或详情字段分别标注来源，不把混合来源压缩为一个行级来源。
