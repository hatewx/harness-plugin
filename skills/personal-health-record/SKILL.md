# 个人健康档案

维护用户指定目录中的本地健康档案。把事实记录、原始医疗材料、长期追踪和派生摘要分开；帮助整理信息，不代替执业医生诊断或治疗。

## 开始前

从本 Skill 目录运行：

```bash
node scripts/profile-config.mjs status
```

- `no-config`：询问用户希望使用的绝对路径。
- `missing-profile`：说明已配置路径不存在，让用户选择修正路径或重新创建。
- 用户确认创建目录后，运行 `node scripts/profile-config.mjs set <绝对路径> --create`。
- 未经确认，不猜测路径、不创建目录、不迁移现有资料。

配置只保存档案根目录路径；健康数据不得写入配置文件。

## 记录模型

创建或重组记录前，读取 [记录模型](references/record-model.md)。核心结构是：成员目录直接位于根目录；每位成员只设 `01-健康档案`、`02-就医记录`、`03-分类追踪` 三个主要目录。

处理成员时：

1. 读取 `成员索引.md` 与候选成员的 `成员资料.md`。
2. 能唯一确定成员时直接继续；同名、代称不明或涉及多人时先询问。
3. 每条记录只属于一个成员。跨成员文件分别建立引用，不复制或混合病史。

## 工作方式

### 记录健康信息

- 症状描述不足以判断紧急性时，先提出完成红旗筛查所需的最少问题。在回答前可以原样保存用户自述，但不得写“无红旗”“可常规观察”或据此延迟就医。
- 当前有效且相对稳定的信息写入 `01-健康档案/健康概况.md`。
- 少量、简单的生活事件追加到 `健康事件.md`。反复发作、需要多个症状字段或用于就诊准备时，表格只保留索引，并使用事件详情附件。
- 数值写入 `健康指标/` 中对应 CSV，保留日期、单位、来源、就诊 ID 和来源文件。
- 一次就医的原始报告、影像、处方和票据只保存在该次 `02-就医记录` 目录。
- `03-分类追踪` 只写主题索引、趋势和结论，通过记录 ID 与相对链接引用事实，不复制原件。
- 摘要是可重新生成的派生内容。不得用摘要覆盖原始记录。

保留用户原话和报告原值。明确区分 `用户自述`、`设备测量`、`报告原文`、`医生诊断`、`整理推断` 和 `待确认`；不得把推断升级为事实。

### 整理既有档案

先盘点目录、文件类型、日期与重复哈希，再提出迁移方案。未经逐项确认，不移动、重命名、覆盖或删除既有资料。发现重复文件时标记候选主副本和引用位置，不自行去重。

### 查询与生成摘要

说明查询覆盖的成员、日期范围和资料范围。结论必须能回到记录 ID 或原始文件；来源不足时明确写“未记录”或“待确认”，不得补全缺失病史。

## 临床审阅角色

当任务包含健康摘要、趋势解释、就诊准备、报告提取或任何医学含义时，完成草稿后必须按 [临床审阅角色](references/clinical-reviewer.md) 做独立审阅。能使用独立子代理时，把草稿和对应来源交给独立上下文审阅；否则在起草结束后进行一次明确分离的第二遍核对。单纯配置路径、创建空目录或机械追加用户原话无需审阅。

审阅意见与事实记录分开呈现。只有用户确认后，才能把审阅建议写入 `待关注事项.md`；不得把审阅意见写成医生诊断。

## 安全边界

- 出现可能危及生命或需要及时处理的表现时，先明确建议寻求急救或尽快就医，再处理档案。
- 不根据档案自行开药、停药、调整剂量或排除严重疾病。
- 需要具体医学解释时，优先依据当前权威医疗来源并提供出处；把来源支持的事实与推断分开。
- 输出面向用户可读，避免制造确定性、恐慌或虚假保证。

## 完成检查

- 成员、单位、记录 ID 和来源完整；日期或时间精度忠实于原始信息，没有制造精度。
- 原始文件只保存一次，引用可解析。
- 就诊、事件、指标和分类追踪之间的关联双向可查。
- 临床审阅已完成或明确说明为何不适用。
- 没有静默修改既有资料或把推断写成事实。
